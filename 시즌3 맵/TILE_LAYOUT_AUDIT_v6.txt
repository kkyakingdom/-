- 839.837 -> 840.837 화면 이동벡터(scale=1): dx=1.060660, dy=0.353553 / 오른쪽+아래 판정=True

- 타일 중심 역변환 샘플 전수(X 1500열 × 대표 Y 7개): PASS
- raw layer 짝수 X -> shift 레이어 패리티 일치: PASS

[렌더링 경로 통일]
- tileCenterToScreen / tilePolygonScreen / screenToTilePoint / centerOnTile 모두 동일 parity 함수 사용
- 타일 격자 가로선도 동일 parity 함수 사용
- terrain/resource raster는 raw X 짝수열만 +0.5 shift 레이어로 분리
- 저배율/고배율 모두 같은 split raster를 사용하여 6배 줌 경계에서 반칸 점프 제거
- 성지/관문/부두/성채/선교/요충지/산길/토지카운터 마커는 tileCenterToScreen 공통 사용

[결론]
839.837과 840.837의 데이터값은 원본 레이어에서 이미 정확했고, 화면 배치의 홀짝 열 선택이 반대로 되어 있던 것이 원인이다.
v6에서는 인게임 짝수 X열이 반칸 내려가도록 모든 타일 관련 렌더링/역변환 경로를 통일했다.
